# Quarry capture

Use the current Quarry schema or `quarry --help` to discover the maintained
write operation. Recall first to avoid duplicate/conflicting knowledge. Capture
only verified decisions, pitfalls and reusable evidence with task/ADR/source
provenance, not a session transcript, secrets or speculative completion claims.
State uncertainty and supersession explicitly. The leader owns durable writes;
read-only specialists return candidate content rather than bypass permissions.
Report the returned receipt or the exact failure; never claim an attempted
capture persisted. Store local tool state under .punt-labs/local/ethos, not
inside source/record trees.
